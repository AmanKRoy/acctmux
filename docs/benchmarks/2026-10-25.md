# Benchmarks, 2026-10-25 (re-run)

Re-run of the [2026-10-23 report](2026-10-23.md) after the MCP SDK v2 migration, the listen-first startup, per-upstream `callTimeoutMs`, retry backoff and the `lib/` split. Same harness ([`scripts/bench.mjs`](https://github.com/AmanKRoy/acctmux/blob/main/scripts/bench.mjs), unchanged), same scenarios where they can be run **without any credentials**. Nothing in this run talked to Google or any other remote API: every benchmark ran inside an unprivileged network namespace (`unshare -rn`, loopback only).

Raw, secret-free results: [`2026-10-25-fake.json`](2026-10-25-fake.json), [`2026-10-25-google-credfree.json`](2026-10-25-google-credfree.json), [`2026-10-25-taylor-credfree.json`](2026-10-25-taylor-credfree.json), [`2026-10-25-startup.json`](2026-10-25-startup.json). The first three regenerate with `node scripts/bench.mjs summarize <file>`.

## What changed in the method

- **Credential-free Google suite.** The real `@dguido/google-workspace-mcp` 3.4.4 binary runs against an empty temporary `HOME` with `{}` placeholder `tokens.json` files (only so account discovery finds `default` and `ai`) and no OAuth client. It starts, answers `initialize` and lists its 54 tools normally; every `tools/call` fails at once with `OAuth credentials file not found` (no network attempt, and the namespace has no network anyway). So this suite measures **memory, session start, `tools/list` and tool surfaces of the real upstream**, but **not** Google latency, and its worker memory is that of a server that never instantiated a Google API client (about 155 MB; the 2026-10-23 workers grew to about 167 MB after real calls).
- **Workload.** Because calls fail fast, the warm phase is almost instant and the `tools/list` phase of all N sessions overlaps; at N = 8 that makes `tools/list` slower for every configuration (stdio too). Compare `tools/list` at N = 1.
- **Supplementary startup script** (`scripts/bench-startup.mjs`; 5 reps per kind): router start until the port accepts, start until the first `tools/list` returns tools, first call to the default account, first call to an account without a worker, idle-kill timing with `idleMs = 2000`, and a 4 s call against a 2 s idle timeout. Upstream: fake (`tests/fake-upstream.mjs`, accounts `default`, `ai`) and the credential-free google-workspace-mcp (`google-workspace` preset, so the `get_storage_quota` warm-up runs and fails fast).
- **Schema parity** check: tools/list of google-workspace-mcp over stdio vs. through the router, each tool compared on `description` and `inputSchema` with the router's `account` property removed.
- **3 repetitions** instead of 5 for the fake suite; warm rounds 30 (fake, default) and 2 (credential-free suites).

## Setup

- Machine: Intel Core Ultra 9 185H (22 logical CPUs), 31.5 GB RAM, Omarchy (Arch Linux), kernel 7.2.8-9-omarchy. **On battery** (`Discharging`, power profile `balanced`); the 2026-10-23 run was on mains. Desktop session and the live acctmux service running (untouched, other network namespace).
- Node v26.12.1, uv 0.11.21, router commit 0cb9f54 (code identical to 452db6d; the later commit only touches docs), MCP SDK v2 (`@modelcontextprotocol/server` 2.4.0) in the repo's `node_modules`.
- @dguido/google-workspace-mcp 3.4.4, mcp-proxy 6.7.21, supergateway 4.2.0 (4.2.1 is the current npm release; the harness pin was kept), workspace-mcp 2.1.2.
- One-minute load average before a cell: fake 1.6-4.6 (median 3.0), credential-free Google 1.5-7.7 (median 5.4, mostly the previous cell's teardown), workspace-mcp 0.8-2.0.
- Runs (UTC): fake 14:50-14:57, credential-free Google 14:57-15:07, workspace-mcp 15:07-15:12, startup and parity scripts after that. One benchmark at a time. No swap used.

## Exact commands

```bash
B=/tmp/claude-1000/bench-2026-10-25                       # scratch, owned by the benchmark
node scripts/bench.mjs setup --work-dir $B/work           # mcp-proxy 6.7.21, supergateway 4.2.0

# fake suite, offline
unshare -rn sh -c "ip link set lo up && node scripts/bench.mjs run --work-dir $B/work --suite fake --reps 3 --base-port 19120 --out $B/fake.json"

# credential-free google-workspace-mcp: temp HOME, symlink to the installed server, placeholder tokens, fake accounts file
G=$B/ghome; mkdir -p $G/.local/share/mcp-servers $G/.config/google-workspace-mcp/profiles/ai
ln -s ~/.local/share/mcp-servers/google-workspace $G/.local/share/mcp-servers/google-workspace
echo '{}' > $G/.config/google-workspace-mcp/tokens.json; echo '{}' > $G/.config/google-workspace-mcp/profiles/ai/tokens.json
# accounts-fake.json: {"clientSecret":"/nonexistent/credentials.json","accounts":[{"label":"default","profile":null,"email":"default@example.invalid","source":"/nonexistent/default"},{"label":"ai","profile":"ai","email":"ai@example.invalid","source":"/nonexistent/ai"}]}
unshare -rn env -i PATH="$PATH" HOME=$G LANG=C.UTF-8 sh -c "ip link set lo up && node scripts/bench.mjs run --work-dir $B/work --suite google \
  --accounts-file $B/accounts-fake.json --configs router,stdio,mcp-proxy,supergateway --reps 3 --warm 2 --timeout 30000 --base-port 19320 --out $B/gwcredfree.json"

# workspace-mcp from the uv cache, offline, no client secret
unshare -rn env -i PATH="$PATH" HOME=$G LANG=C.UTF-8 UV_CACHE_DIR=~/.cache/uv UV_PYTHON_INSTALL_DIR=~/.local/share/uv/python UV_OFFLINE=1 \
  sh -c "ip link set lo up && node scripts/bench.mjs run --work-dir $B/work --suite google --accounts-file $B/accounts-fake.json \
  --configs taylor-http-direct,taylor-stdio-direct --reps 3 --warm 2 --timeout 30000 --base-port 19720 --out $B/taylor-credfree.json"

# startup / cold account / idle-kill (supplementary script), 5 reps each, idleMs 2000
unshare -rn env -i PATH="$PATH" HOME=$G sh -c "ip link set lo up && node startup.mjs --kind fake --reps 5 --port 19500 ... && node startup.mjs --kind gw --reps 5 --port 19520 ..."
```

## Limitations

- No Google traffic: warm-call latency, the first real call per account, token refresh behaviour, the workspace-mcp rebind failure and account identity were not measured. Worker memory is that of servers without Google API clients.
- On battery with the `balanced` profile; one-minute load up to 7.7 before some cells. Latency medians at the millisecond level move by 10-30 % between reps (see the per-rep brackets).
- 3 repetitions, one machine, one afternoon. PSS depends on what else maps the same files; the live router (same Node binary and SDK paths elsewhere) was running.
- `router-taylor*` is broken in the harness since the SDK v2 migration (see Coverage); the harness itself was not changed for this run.
