### 1. Bugs and regressions from the changes (b)

| # | Sev | Tag | Finding |
|---|---|---|---|
| N1 | Med | CONFIRMED (repro) | Pools re-run non-retryable tools on another account after a login failure. `router.mjs:557-561` treats every `upstream:false` as "never ran", but `forward()` also returns `upstream:false` after a `resultMatch` hit and after a stderr auth banner arriving mid-call, when the call had already reached the upstream. Repro: pool `[b,c]`, `tools:["whoami"]`, b auth-broken: `echo` (not in the retry list) went to b and then also ran on c. Breaks the documented "retries need an explicit list" rule. Fix (XS): return `{started:false}` only when `child()` threw; rotate only then (or when the tool is in `pool.tools`). |
| N2 | Med (docs) | CONFIRMED | CONFIG.md:74 still said start failures and login failures are "Never retried ... returned to the caller exactly as for a plain account". C8 reversed that; N1 widens it. |
| N3 | Low-Med | CONFIRMED | Startup now waits for every account of a broken upstream: 4 hanging accounts at a 1.5 s connect timeout took 6.3 s vs 1.7 s before; at the default 15 s the 6-key Tavily example is about 90 s with no listener. Fix: listen first and load in the background, or put a time budget on the fallback. |
| N4 | Low | CONFIRMED | A selector clash is not account specific, yet `loadBase` spawns every account to rediscover it, and the clashing upstream is retried every 30 s of traffic. Fix: make the clash error terminal. |
| N5 | Low | CONFIRMED | A recovered upstream is invisible to the request that triggers its retry, because the retry runs in the background; when it loads it can rename other upstreams' tools (`whoami` became `good__whoami`). This is C6, now triggered with no visible cause. |
| N6 | Low (design) | CONFIRMED | An account's `allow` replaces the `*` allow, so it can widen it. Documented, but asymmetric with "a `*` deny can never be lifted"; the test title said "narrows" and never exercised account b. |
| N7 | Low | CONFIRMED | No validation of `selector` (`""` accepted); policy keys naming no account or pool are silently ignored, so a typo'd per-account deny is a silent no-op. |
| N8 | Low | CONFIRMED | `env` values are not `~`-expanded, which is why `config.multi.example.json` hard-coded `/home/<your username>` (shipped in the tarball). |

### 6. Verdict

- Ship for personal use: yes. All review-02 correctness and security fixes are real and mutation-proven; the live-config risk from C1 is gone. N1 matters only for pools with auth-broken members.
- Publish publicly: not today, but close (about half a day, fixes 1-4). Blockers: one small retry-contract bug (N1); docs that contradict the fixed behaviour, three of them about safety (pool retries, credential reading, bind address); repo and package hygiene (private repo, 5 MB of JSON in the package, a personal path in an example).
- Would star: yes, once published with fixes 1-3. Niche, well evidenced, honest about when not to use it; pools are the original part; reach limited to stdio upstreams until remote/OAuth.
- Single blocker: the docs again promise safety behaviour the code does not have (CONFIG said pool start and login failures are "never retried"; HEAD retried them, including a non-retryable tool that had already reached a login-broken member). Fixing N1 and a real docs pass across README and CONFIG turns this into a yes.
