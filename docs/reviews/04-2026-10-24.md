### 2. Architecture

Every new finding traces back to "load fully, then listen" (R1, R2, N3, the C2 class). Listening immediately and loading tools lazily, with `tools/list` waiting a bounded time for the first load, would remove the class. Tool names should depend on the config, not on which upstreams are up (C6/N5).

### 3. Differentiation (rechecked today)

taylorwilsdon #926 still OPEN, PRs #928 and #1049 still OPEN, latest release v2.1.2 (2026-10-21). New and close: `antoniofulg/mcp-account-router` (MIT, 0 stars, created 2026-10-11): local gateway with ordered per-server profiles, quota failover limited to an explicit read-only `safeTools` list, result cache, request de-duplication, HTTP and stdio upstreams, mandatory bearer token. It overlaps with the pool idea (including the explicit retry list) but lacks a caller-chosen account selector, lazy idle-killed per-account workers, per-account policy and prompts/resources; it does better on remote/HTTP upstreams, mandatory auth and caching. Cite it in README "Related projects"; pools alone are no longer unique, while selector plus lazy shared workers plus per-account policy still are. `elzinko/google-mcp-multi-account` is Google-only and macOS-only. The rest of the review-02 table holds.

### 6. Verdict

- Ship for personal use: yes. Nothing here endangers the live setup as long as the live config keeps `authRequired` (R5); R1 would only bite if three profiles broke at once.
- Publish publicly: not yet, but close: about half a day for fixes 1-4 plus the repo rename and visibility change. The remaining blockers are hygiene and one docs-to-code safety gap, not design. The private repo means every npm link returns 404.
- Would star: yes, once fixes 1-4 are in and the repo is public. Niche, carefully evidenced, honest about when not to use it. The pools now have one tiny competitor.
- Single blocker: the shipped examples quietly turn off the safety behaviour the README promises (R5). This is the third review in a row where docs or examples promise safety behaviour a user would not actually get.
